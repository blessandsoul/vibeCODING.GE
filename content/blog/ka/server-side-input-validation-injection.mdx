<h2 id="injection-boundary">სად იწყება injection რისკი?</h2>
<p>Injection ჩნდება მაშინ, როცა untrusted მნიშვნელობა interpreter-მდე მიდის ისე, რომ პროგრამა მას მონაცემად და ბრძანებად ვეღარ არჩევს. SQL injection-ში ეს interpreter მონაცემთა ბაზაა. Command injection-ში ეს შეიძლება იყოს ოპერაციული სისტემის shell ან ისეთი ბიბლიოთეკა, რომელიც სისტემურ ბრძანებას ასრულებს. რისკი მხოლოდ ტექსტურ ფორმაზე არ ვრცელდება: filter, sort, file name, URL, import და ადმინისტრატორის პარამეტრიც input-ია.</p>
<p><a href="https://cheatsheetseries.owasp.org/cheatsheets/Input_Validation_Cheat_Sheet.html">OWASP Input Validation Cheat Sheet</a> გვირჩევს validation ადრეულ გამოყენებას, მაგრამ პირდაპირ ამბობს, რომ ის SQL injection-ისა და XSS მთავარი თავდაცვა არ უნდა გახდეს. ამიტომ review-ში ორი ცალკე კითხვა დასვით: მნიშვნელობა სწორად არის თუ არა შეზღუდული და interpreter იღებს თუ არა მას პარამეტრად, კოდის ნაწილის ნაცვლად.</p>
