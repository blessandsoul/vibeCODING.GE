<h2 id="xss-meaning">რას ნიშნავს untrusted HTML რისკი?</h2>
<p>Cross-Site Scripting, ანუ XSS, ხდება მაშინ, როცა თავდამსხმელის მიერ კონტროლირებადი მნიშვნელობა ბრაუზერში კოდის ან აქტიური markup სახით სრულდება. წყარო შეიძლება იყოს კომენტარი, პროფილის სახელი, Markdown, URL fragment, search query, ფაილის სახელი ან მესამე მხარის API პასუხი. საკითხი არ შემოიფარგლება <code>&lt;script&gt;</code> ტეგით. კონკრეტული browser context და renderer წყვეტს, რომელი სიმბოლო ან თვისება ხდება საშიში.</p>
<p><a href="https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html">OWASP XSS Prevention Cheat Sheet</a> სხვადასხვა output context-ს სხვადასხვა დაცვას უკავშირებს. ამიტომ review არ უნდა დაკმაყოფილდეს კითხვით, „არის თუ არა input გაწმენდილი“. ჯერ უნდა ჩაიწეროს სად ინახება value, სად გადადის და რა ფუნქცია ქმნის საბოლოო DOM-ს.</p>

<p>ეს დამოკიდებულია პროდუქტზე. თუ rich text აუცილებელია, საჭიროა მცირე allowlist, sanitizer და renderer ყველა გზის ტესტი. თუ ფუნქცია არ არის საჭირო, მისი გამორთვა ამცირებს ზედაპირს, თუმცა სხვა content path-ები მაინც უნდა შემოწმდეს.</p>
